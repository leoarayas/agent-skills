# IMAP mailbox triage

1. Locate the mailbox credential under `~/.openclaw/credentials/imap/` and use it in-process; never print its host, username, or password.
2. Verify read-only access with Python `imaplib.IMAP4_SSL`: log in, select `INBOX` with `readonly=True`, and call `status('INBOX', '(MESSAGES UNSEEN UIDNEXT)')`; report only counts because headers and credentials are private.
3. Inventory unread mail by sender domain before moving anything: run `UID SEARCH UNSEEN`, fetch only `BODY.PEEK[HEADER.FIELDS (FROM SUBJECT DATE)]`, parse the address domain with `email.utils.parseaddr`, and aggregate counts plus at most two samples per domain; use `PEEK` so the review preserves unread state.
4. Create organizational folders below `INBOX.`, for example `INBOX.Cuarentena-Comercial`, `INBOX.Notificaciones-Operativas`, and `INBOX.Revisar-Manual`; cPanel/Dovecot requires the `INBOX.` prefix, so a top-level folder name will be rejected.
5. Classify by sender domain first: put known operational domains in notifications, known unsolicited-sales/phishing domains in quarantine, and unknown, personal, financial, security, or potentially legitimate domains in manual review; do not classify a sender as safe from subject keywords alone. When one operational sender supplies most of the mail, split its traffic by subject class before moving anything, because one host's alerts collapse into a single domain and read as one undifferentiated class.
6. After the owner authorizes movement, group message UIDs by destination and use `UID MOVE <comma-separated-uids> <folder>`; this keeps messages unread and makes the organization reversible. Do not delete or expunge mail as part of triage.
7. For a mailbox with more than 1,000 messages, run `UID SEARCH SINCE` for the current month, prior month, and a historical cutoff before fetching headers; sample only the newest 100 unread headers first so current operational mail is not buried under migration backlog.
8. Create folders below `INBOX.` and group infrastructure alerts, delivery bounces, verified human mail, and residual historical mail separately; use server-side `UID SEARCH FROM <address>` for known automated senders, then compact consecutive UIDs into ranges before one `UID MOVE` per destination so large moves complete without per-message timeouts.
9. Move only residual mail older than the chosen cutoff into an `INBOX.Archivo-Historico-<year>` folder after known operational and human classes are extracted; keep recent mail visible for review.
10. Verify `MESSAGES` and `UNSEEN` for INBOX and every destination folder after the move; report moved counts and state explicitly that nothing was deleted.
11. Stop the upstream source when the flood is an alert storm, because filing the mail leaves it regenerating; silence the sending host's per-class alert toggles rather than deleting mail, and confirm on the MTA log that its last alert predates the change. Follow `cpanel-csf-alert-noise` for a cPanel CSF/LFD source.
12. Parse the folder list from the raw LIST response instead of assuming quoted names: cPanel/Dovecot returns `(\HasNoChildren) "." INBOX.Folder`, where the delimiter is `.` and the name is unquoted. A parser that takes the last quoted token resolves to the delimiter and reports one folder instead of all of them, which silently skips the search. Extract with `^\([^)]*\)\s+"([^"]*)"\s+(.*)$` and strip surrounding quotes from group 3.
13. When a financial or account-security email needs a decision, reconstruct the whole event sequence before asking the owner: search every folder including Trash and Spam, fetch full bodies, normalize every timestamp to one timezone, and order the events. The causal order decides the case: a purchase followed by PIN, recovery-email and two-factor changes points to the account holder's own onboarding, while a purchase after those changes points to an attacker. State what the evidence cannot show, such as the source IP when the provider's mail omits it, and recommend rotating any credential left sitting in a Trash folder regardless of who created it. Never repeat a PIN, verification code or recovery key in the report.

Report folder names and counts only by default. Surface only a known human contact, verified financial provider, or account-security event. Treat lookalike bank, government, delivery, and invoice domains as quarantine candidates unless independently verified.
